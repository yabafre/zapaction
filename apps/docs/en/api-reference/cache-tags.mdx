# Cache Tags

## Why tags

Tags let the server and client share one invalidation vocabulary.

## Register tags on client

```ts app/providers.tsx
import { setTagRegistry } from "@zapaction/query";

setTagRegistry({
  todos: [["todos"]],
  todoById: ({ input }) => [["todos", "by-id", (input as { id?: string })?.id ?? "unknown"]]
});
```

## Attach tags on server actions

```ts app/actions.ts
import { defineAction } from "@zapaction/core";

export const updateTodo = defineAction({
  input: someSchema,
  output: resultSchema,
  tags: ["todos", "todoById"],
  handler: async ({ input }) => {
    return updateInDb(input);
  }
});
```

## Server revalidation

`defineAction` triggers `revalidateTags(tags, revalidation)` when tags are present.

```ts packages/core/src/revalidateTags.ts
export type CacheLifeProfile = string | { expire?: number };
export type RevalidationMode = "revalidate" | "update";
export type RevalidateTagsOptions = {
  mode?: RevalidationMode;
  profile?: CacheLifeProfile;
};

export async function revalidateTags(
  tags?: readonly string[],
  options?: RevalidateTagsOptions
): Promise<void>

export async function updateTags(tags?: readonly string[]): Promise<void>
```

- **Default (`mode: "revalidate"`)**: calls Next.js 16 `revalidateTag(tag, profile)` (defaults to `"max"` for stale-while-revalidate; works in Server Actions and Route Handlers) and falls back to single-argument `revalidateTag(tag)` on Next.js 15.
- **Immediate (`mode: "update"` or `updateTags`)**: calls Next.js 16 `updateTag(tag)` for read-your-own-writes expiration inside Server Actions (falls back to `revalidateTag(tag)` on Next.js 15).

## Client invalidation

`useActionMutation` triggers `invalidateTags(queryClient, tags)` after success.

```ts packages/query/src/invalidateTags.ts
export async function invalidateTags(
  queryClient: QueryClient,
  tags?: readonly string[]
): Promise<void>
```
